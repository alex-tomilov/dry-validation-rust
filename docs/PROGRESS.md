## What Has Been Accomplished

### Milestone A (Complete)

- Upstream `dry-validation` pinned at 1.11.1.
- Differential harness with 80+ schema cases and 6 unsupported-construct cases.
- Isolated-subprocess execution with timeout and memory guards.
- `script/verify` one-command gate.
- Package metadata audit.
- 5 CI workflows, Dependabot, issue/PR templates.

### Milestone B (Complete)

- Nine schema slices delivered (required/optional keys, types, nesting,
  predicates, coercion, composition, messages, result API, unsupported constructs).
- Rust engine split into 6 modules (plan, engine, coercion, predicates, error, ruby_bridge).
- Typed `PredicateArg` enum.
- Recursion depth guard (default 128).
- 18 Rust unit tests, including native coercion boundary cases.
- 64-input malformed-input resilience corpus.
- `cargo test` and `cargo clippy` in CI.

## What Is Next

The native predicate error-propagation risk is resolved, engine calls now use a typed native result, and comparisons, parity, and common size predicates have pure-Rust paths with explicit Ruby fallbacks for unsupported primitive representations and custom values. Params scalar coercion has native fast paths for common numeric and ISO temporal inputs while Ruby remains the explicit compatibility fallback. JSON plan parsing enforces its depth limit without a separate pre-scan, and ADR 002 retains JSON after local MessagePack and direct-walking measurements. Criterion reports now cover the native comparison, size, and parity predicate paths in addition to plan compilation and coercion, with all reports retained by non-blocking CI; README records a local 100-sample predicate baseline. The project-local `benchmark-matrix` skill runs the reproducible measurement workflow, `script/verify` bootstraps its Rust advisory tool, and native-gem workflows prepare the `rb-sys-dock` Cargo registry mount, explicitly install host Rustup targets, and install the locked bundle in their build containers; the remaining roadmap priorities are unchanged.

1. Build a dedicated 50-case rule corpus (see Milestone C file for distribution).
2. Complete remaining C-Q1 and C-Q2 code-quality tasks; the P0 `Message` Data migration (C-Q5) is complete.
3. Stress-test rule dependencies and isolation, then wire the rule corpus into differential CI.
4. Resolve the roadmap's 50-field versus 100-field P50 criterion and complete the remaining Performance Proof work after Milestone C; Criterion plan-compilation, coercion, and predicate reports run in non-blocking CI, while the six full-schema scenarios have local 100-sample results recorded in README. Type-error code/text avoid native allocations and Phase 1 path-vector reuse, Ruby class caching, and Steps 3.1–3.5 (benchmark matrix, allocation gate, plan deserialization/Ruby-level engine fuzzing, and profiled GVL-path optimizations) are complete.
5. Configure the RubyGems trusted publisher for `rubygems-push.yml`, then validate and publish the P0 precompiled gems so the documented recommended path becomes available.

## Known Debt and Risks

- Benchmark matrix results are limited to one x86_64 Linux host and three runs per scenario; cross-host evidence and native-allocation measurement remain pending (Milestone D). Ruby allocation regressions and baseline recording are limited to Ubuntu Ruby 3.3.
- Native scalar fast paths intentionally cover only common finite literals; arbitrary precision, numeric overflow, time-only values, and broader Ruby date/time syntax still cross into Ruby.
- Plan-transport evidence is limited to one x86_64 Linux host and definition-time compilation; reconsider JSON only with a demonstrated multi-host definition-time bottleneck.
- Criterion plan-compilation benchmarks cover 5, 50, and 200 fields; coercion benchmarks cover five scalar groups; predicate benchmarks cover comparison, size, and parity groups; and a local end-to-end benchmark covers the six Ruby schema-throughput scenarios. Their recorded baselines are limited to one x86_64 Linux host. The roadmap's 100-field P50 gate is not represented by a benchmark case.
- P0 precompiled-gem builds and signed publication workflow are configured and cross-compilation errors are resolved, but they are not yet published; RubyGems trusted-publisher setup is still required (Milestone F).
- No RBS type signatures (Milestone F).
- Predicate-composition blocks support sequential predicate calls only; boolean dry-logic AST composition remains unsupported.
- Custom dry-types are Ruby-owned direct `value(type)` fields; custom array-member types and dry-schema's type-specific failure messages remain unsupported.
- I18n schema messages require applications to include the optional `i18n` gem.
- Security advisories depend on GitHub private vulnerability reporting remaining enabled.
- Governance documentation may be disproportionate to project scale.
- Naming/affiliation with dry-rb not yet discussed (Milestone G).
- `edition = "2024"` / `rust-version = "1.85"` may exclude contributors.
